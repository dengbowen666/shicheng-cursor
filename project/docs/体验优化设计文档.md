## 0. 定位与边界

**唯一用户 = 项目所有者本人。** 本轮目标只有一个：把"能看懂示例"升级为"能顺畅造出自己的攻略"，消除从浏览态切到编辑态路上的每一处硌手。

**明确不做（边界外）**

- 不改任何文案：题名、按钮字、提示语、印章文一律保留现有语汇。
- 不以"给别人看"为目标调整字号、对比度、字体栈——当前可读性满足本人使用。
- 不引入后端；继续 localStorage + 现有腾讯 Key 机制。

**五条设计原则**

1. **展示模型 = 编辑模型**：界面能展示的（跨城、"翌日赴某地"、精确到分的时刻），用户必须能自己造出来、改得动。
2. **一个动作一条撤销路径**：所有变更进同一栈，toast 不再自带第二套闭包撤销。
3. **微调不毁数据**：增删点、换顺序只影响相关段，不重置已取到的真实路线。
4. **建议有记忆且按天隔离**：忽略过的提示不再冒出来，也不串到其他天。
5. **默认值诚实**：取到真值就用真值，取不到就明确标"估"，不伪装精确。

## 2. 分项改造方案

### O01 · 跨城攻略可达【P0】

**现状**：`createTrip` 只接一个 `city`，所有 `days[].city` 初始化为同城；`addDay` 沿用最后一城。seed 示例的"大理→丽江"是代码写死的，UI 无入口。但 `Trip.cities: City[]` 与 `DayPlan.city: string` 的数据模型本身支持多城。

**目标态**：任意一天的城市可单独指定；`Trip.cities` 由各天 `city` 自动推导、去重、按首次出现顺序排列，不再单独维护。

**改动**

- `DayPanel.vue` 卷首头部：把"{{ day.city }}"改成城市选择器（复用现有 `cityStore.searchCities`），变更走 `setDayField(dayIndex, { city })`。
- `trip.ts` 新增 `setDayCity(dayIndex, city: City)`：写 `day.city`，并调用 `syncCities(trip)` 重算 `trip.cities`；对非首城的跨城日，`void refineDay(dayIndex)` 重取路线。
- `syncCities(trip)`：从 `days` 提取城市名 → 按 `cityStore` 查回 `City` → 去重保序 → 写回 `trip.cities`。在 `createTrip`／`setDayCity`／`removeDay`／`normalizeTrip` 后调用。
- `addDay` 保留沿用末城作为默认值（合理），但用户可立即改。

**验收**：新建 3 日行程 → 把 Day2 改成"丽江" → 首页地图出现两城印记 + 跨城虚线 → `DayPanel` 显示"翌日·赴丽江"分隔 → 刷新后保持。

### O02 · 出发时间可编辑【P0】

**现状**：`departTime` 只在 seed 赋值，UI 无任何写入点；`DayPanel.vue:155` 显示为文本，看着像能点。整条时间轴从它起算。

**目标态**：每天出发时间可编辑，与停留时长同一套"点一下变输入框、Enter/失焦提交"的就地编辑模式。

**改动**

- `DayPanel.vue` 卷首"09:00 出发"改为就地编辑控件（`editingDepart` / `departDraft`，参照 `startStay`/`commitStay`），校验 `HH:MM` 合法后 `setDayField(dayIndex, { departTime })`。
- 提交后 `deriveDay` 自动重算；无需改 store。
- `setDayField` 纳入 O03 统一快照。

**验收**：把 Day1 改成 08:30 → 时间轴首个到达时间相应前移 30 分钟 → 撤销可回到 09:00。

### O03 · 撤销系统统一【P0】

**现状（三处硬伤）**

1. 双轨：`undoStack` 快照 与 toast 闭包撤销并存。`removePoi`（`DayPanel.vue:102`）先让 `removeFromDay` 压快照，toast 撤销又调 `addToDay` 再压一次快照——点一次"撤销"栈里多两条，越撤越乱。
2. 覆盖不全：`updateTrip`、`updatePoi`（停留）、`setSegmentMode`、`toggleBase`、`addDay`、`updateExpense`、`addCustomPoi`、`addPoi` 均无快照；其中 `setSegmentMode` 在 `TripEditorView.vue:412` 的 toast 连闭包撤销都没给。
3. 全局栈不认当前攻略：`undo()` 恢复了 `entry.tripId` 的数据，但 `activeTripId` 不变——在 A 攻略按撤销可能改了 B 的数据，界面毫无变化。

**目标态**：单一快照栈，所有变更都进栈；UI 的"撤销"统一调 `trip.undo()`。

**改动**

- `trip.ts` 所有 mutation 函数入口统一调 `snapshot(tripId, label)`：补上 `updateTrip`／`updatePoi`／`setSegmentMode`／`setDayField`／`addDay`／`updateExpense`／`addCustomPoi`／`addPoi`／`toggleBase` 涉及的原子操作。
- `undo()` 恢复后，若 `entry.tripId !== activeTripId.value`，则 `activeTripId.value = entry.tripId`，让撤销结果可见。
- UI 层移除所有闭包撤销：`DayPanel.vue:102,134`、`SmartAssist.vue:49,83,98,118`、`ExpenseDrawer.vue:108,128,150`、`TripEditorView.vue:181`。toast 的 action 一律传 `undefined`，或统一写成 `ui.toast(msg, '撤销', () => trip.undo())`。
- 保留 12 条上限（`trip.ts:146`）；可选：撤销时把 label 回显到 toast，便于确认撤的是哪一步。

**验收**：连续做"加入→改停留→设驻地→改交通→删点"五步，逐步撤销五次，每次画面都回到上一步的真实状态，且始终停留在同一攻略。

### O04 · `rebuildSegments` 改增量【P0】

**现状**：`trip.ts:246-273` 删光当天所有段，按 `poiIds` 顺序重建；`oldModes` 只保留 `mode`。`path`／`cost`／`durationMin`／`lineNos`／`transferCount`／`estimated=false` 全部丢失，再异步 `refineDay` 重取。调用方多达 6 处（增删点、跨日移动、换顺序、顺路重排、设驻地）。"微调一次、整天前功尽弃"。

**目标态**：只改动受影响的段，未变段**完整保留**（含真实路线）。

**改动**（`trip.ts` 重写 `rebuildSegments`）

```
stops   = day.poiIds.filter(id => pois[id].role !== 'base')
desired = 相邻 stop 的 "from|to" 键集合

① 清理：day.segmentIds 中键不在 desired 的段 → delete t.segments[sid]，移出 segmentIds
② 复用/新建：对每个 desired 键
     existing = day.segmentIds 中键匹配的段
     if existing → 原样保留（path/cost/estimated=false 全部不动）
     else        → estimate() 建段，estimated = true，加入 segmentIds
③ 仅当 ② 中有新建段时才 void refineDay(dayIndex)
```

**约束**：`mode` 沿用旧段（已有逻辑保留）；pinned 段（见 O05）在 ① 中豁免删除、在 ② 中豁免覆盖。

**验收**：取到真实路线的 A→B→C → 在末尾加一个 D → A→B、B→C 的"估"字与真实路径不闪现、不重新请求，只有 C→D 标"估"并补取。

### O05 · 交通段显式可编辑【P1】

**现状**：段由 `poiIds` 顺序隐式生成，不能插中间点、不能单独删段、不能把某段走法固定住——而 O04 的全量重建正是这个模型的副作用。

**目标态**：段成为**可独立操作的对象**，同时保留"自动连线"作为默认行为。

**改动**

- `TransportSegment` 增加 `pinned?: boolean`（`types/index.ts:33`）。
- O04 的 `rebuildSegments` 对 `pinned` 段豁免删除与覆盖。
- `DayPanel.vue` 交通条增加两个操作：
  - **固定走法**：调用 `setSegmentMode` 时可选 `pinned=true`（SegmentPicker 增加"固定"复选），此后 rebuild 不再改它。
  - **插入经停**：在段的两点之间搜索并插入一个 POI（`addToDay(poi, dayIndex, atIndex)`），O04 自然生成两段。
- 删段＝删掉该段两端之间的某个 POI（`removeFromDay`），不提供"只删线不删点"——避免段与 `poiIds` 失配。

**验收**：固定 A→B 为"骑行" → 后面增删其他点 → A→B 仍是骑行且真实路线不丢；在 A→B 之间插入"咖啡馆" → 变成 A→咖啡馆→B 两段。

### O06 · 智能建议有记忆且按天隔离【P1】

**现状**：`dismissed` 是 `SmartAssist.vue:26` 的组件本地 `ref`，刷新即丢；`reorder`／`overload`／`underload` 用全局单键，Day1 忽略会连累 Day2、Day3；`dist-${seg.id}` 的 `seg.id` 每次 rebuild 都变（`uid()`），忽略形同虚设。

**目标态**：忽略状态持久化、按攻略＋按天隔离、键稳定。

**改动**

- 新增 localStorage 键 `shicheng:dismissed`，结构 `{ [tripId]: string[] }`；`ui.ts` 提供 `isDismissed(tripId, key)`／`dismissKey(tripId, key)`（按攻略+按天隔离，实现签名带 `tripId`）。AI 卡的忽略也复用此机制（键 `ai@${dayIndex}`）。
- 稳定键改造：`overload@${dayIndex}`、`reorder@${dayIndex}`、`underload@${dayIndex}`、`dist@${fromPoiId}>${toPoiId}`（用 POI id，不用 segment id）。
- `SmartAssist.vue` 把本地 `dismissed` 换成 ui store 调用；切天、刷新后保持；不同攻略互不干扰。

**验收**：在 Day1 忽略"顺路重排" → 切到 Day2 仍能看到该天自己的重排建议 → 刷新后 Day1 的仍不出现；把某段交通方式改了又改回，`dist@` 忽略依然生效。

### O07 · `dayStats` 口径统一【P1】

**现状**：`timeline.ts:53` 的 `stops = day.poiIds.filter(id => !!pois[id])` 未排除 `role='base'`，而 `deriveDay`（`:26`）排除了。于是有驻地时 `stopCount` 虚高 1，`SmartAssist` 的过载判断（`stopCount > overloadPoiCount`）可能误报，`ItineraryDrawer`/`DayPanel` 显示的"处停留"也偏大。

**目标态**：`dayStats` 与 `deriveDay` 用同一口径。

**改动**

- `timeline.ts:53` 改为 `day.poiIds.filter(id => pois[id] && pois[id].role !== 'base')`。
- 顺带：`dayStats` 内部调用 `deriveDay(day, pois, segments)` 时未传 `expenses` 与 `prevCity`，不影响统计，但为口径一致可保持现状。

**验收**：某日 3 个景点 + 1 个驻地 → "处停留"显示 3，不触发过载。

### O08 · 状态泄漏【P2】

**现状**：`onSelectSegment` 设 `selectedSegmentId` 并开 modal；`closeModal()`（`ui.ts:68`）只清 `modal`，不清 `selectedSegmentId`。弹层虽因 `selectedSegment && modal==='route'` 双重条件不误显，但残留 id 污染状态。`onKeyEsc` 也只清 `selectedPoiId`。

**改动**

- `ui.ts` 新增 `clearSelection()`，同时清 `selectedPoiId` 与 `selectedSegmentId`。
- `closeModal()` 调用 `clearSelection()`；`onKeyEsc` 在关 modal 分支一并调用。

**验收**：开交通弹层 → Esc 关闭 → 再点"忆游"等入口，不会有旧段的幽灵状态。

### O09 · 导入覆盖保护【P1】

**现状**：`trip.ts:478` 同 id 直接 `trips.value[idx] = trip`，静默覆盖。误导入旧备份会无声吞掉当前进度。

**目标态**：导入前显式列出冲突，由用户选择覆盖／跳过／另存为新攻略。

**改动**

- `importData(json, policy: 'overwrite' | 'skip' | 'clone' = 'overwrite')`：命中同 id 时按 policy 处理；`clone` 则重新分配 id 并改题名后缀。
- 返回值增加 `conflicts: string[]` 与 `skipped: number`。
- `SettingsModal` 导入前先 dry-run（`policy='skip'` 预检）拿到冲突列表，弹确认层让用户选，再执行真正导入。

**验收**：导入含同 id 的旧 JSON → 弹出冲突列表 → 选"跳过"后当前攻略完好；选"另存"后两份并存。

### O11 · 纸色底图路网可辨【P1】

**现状**：`global.css:229-231` 的 `gl-paper` 用 `saturate(.62) ... sepia(.10)` 把真实路网与宣纸底压成同一色阶；再叠 `gl-wash opacity .28`（`:232-238`）。名义上"真实·纸色"保留路网，实际看不清街巷，与"找路"这一核心用途冲突。

**目标态**：保持宣纸调，但路网必须可辨。

**改动**

- `gl-paper` 调参：`saturate(.72) brightness(1.02) contrast(1.12) sepia(.08)`。
- `gl-wash` opacity 从 `.28` 降到 `.18`。
- 保持"真实·标准"档不变，作为对照。

**验收**：同一路段切"纸色"与"标准" → 纸色下主干道与街巷仍可辨，色调仍是米白青赭。

### O12 · 记账图表信息结构【P2】

**现状**：`ExpenseDrawer.vue:51-61` 的环形图只编码 `ratio` 一个数，且中心已显示"¥已用／预算¥"；却占据抽屉首屏 150px 的半幅。分类柱状图（`:63-76`）信息量高得多，被挤在另一半。

**目标态**：把空间给分类柱状，三态（正常／结余／逾制）用数字 + 颜色表达，不靠环形。

- 无预算分支（`:199-211`）已是数字 + 柱状，保持一致。

**验收**：打开账本 → 首屏直接看到分类柱状与结余数字，不再有一个只表达百分比的环。

## 3. 优先级与分期

| 期 | 编号 | 主题 | 为什么先做 |
|---|---|---|---|
| **一期·让攻略能被造出来** | O01 O02 O04 | 跨城、出发时间、增量重建 | 这三条不解决，用户的攻略永远只是示例的旁观者 |

## 4. 回归验收清单（用户真实流程走查）

1. 首页新建 3 日攻略 → 选城市、定天数、改题名 → 进入编辑器。
2. 把 Day2 改成另一座城 → 首页出现两城印记与跨城虚线，时间轴显示跨城分隔。
3. 把 Day1 出发时间改成 08:30 → 首个到达时间前移。
4. 搜索并加入 4 个 POI → 交通段自动连线；把其中一段固定为骑行。
5. 有 Key 时等真实路线落地（"估"字消失）→ 再插入一个经停点 → 旧段"估"字不闪现。
6. 打开账本记三笔 → 改一笔、删一笔，每步可撤销且回到正确状态。
7. SmartAssist 忽略"顺路重排" → 切天、刷新后不再出现；其他天仍出现。
8. 归档 → 首页"已行卷"可见 → 恢复 → 攻略内容无损。
9. 导出 JSON → 清库 → 导入 → 冲突提示正常，选择后数据符合预期。
10. 桌面折叠两侧面板 → 地图宽度 ≥ 55vw；移动端上拉抽屉三档顺畅。
11. `npm run typecheck` 与 `npm run build` 通过；`npm run shoot` 11/11 保持。
