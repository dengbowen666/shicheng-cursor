一、产品定位：拾程是什么

1.1 一句话定位

「拾程」是一个国风水墨风格的全国旅行攻略编辑器：在水墨中国地图上搜到你想去的任一城市，下钻进城市地图，自己挑景点、订住宿、逐段选交通方式——打车段地图上跑小车、步行段画脚印；出发前拆锦囊，路上「该出发了」会催你、每到一处盖一枚「已至」朱砂印；回来导出一幅国风长卷。攻略全程存于本机浏览器，一人一世界。

站名「拾程」谐音「时辰」——把一段段时辰拾进画卷；印章形制的站标以朱砂印文「拾程」呈现，用于顶栏、加载态、导出落款三处。

1.2 三条命的旅程模型（产品骨架）

拾程的整个信息架构围绕攻略的「三条命」组织——这是比功能列表更本质的产品骨架，所有模块都挂在这三条命上：

① 做之前 · 编辑器

逛城市攒心愿（收藏池）→ 排日程（分日/拖拽/驻地）→ 连线选交通（小车/脚印/公交/骑行）→ 智能辅助与时间推算 → 朱笔批注圈画。占产品约 60% 的分量，是核心。

② 走之中 · 今天视图

出行当天打开：行前锦囊拆封 → 按时间自动推进 → 「该出发了」朱砂催促 → 一键唤起腾讯地图导航 → 每到一处盖「已至」印 → 随手记账、雨备换点。

③ 回来后 · 回顾与沉淀

忆游回顾（印章分布+花费曲线+题跋集）、归档「已行卷」、首页城市印记盖「行」字、导出长卷与打印版、全程回放彩蛋；此后随时可切首页「行迹」态，历次行脚汇于一图（4.17）。

核心理念自 v1 一脉相承：一张地图走天下——出发前高效做功课，旅途中点一下解决衣食住行。四大功能（一图看全程 / 信息聚合 / 一键导航 / 开销+时间记录）全部保留，但重心从「看攻略」移向「做攻略」。

1.3 边界声明

  • 城市库 = 内置 205 城清单（D93）：各省会 + 热门地级市/州府，含名称、省份、GCJ-02 中心坐标与 adcode，是「可入城」全集；搜索在清单内过滤。POI / 路线 / 天气 / 逆地理等内容数据仍运行时取数（腾讯 WebService + Open-Meteo），不受清单限制；三城种子仅作兜底与演示。
  • 攻略以单城市为主，支持跨城：「大理→丽江」这类跨城行程可表达，但跨城交通段只做示意（不录铁路班次，时间轴用「翌日 · 赴丽江」分隔卡缝合）。
  • 单一地图界面：所有功能以抽屉（drawer）+ 弹层（popup）展开，不做浏览/编辑双模式切换；两个页面级视图：首页「我的攻略」与「攻略编辑器」。
  • 仅本人使用：无账号、无云端同步；攻略存 localStorage，换设备用 JSON 导出导入迁移。静态站点无服务器数据，别人猜到 URL 也只能看到空应用。
  • 零定位权限：「足迹墨线」（GPS 轨迹）方案已评审并放弃；忆游回顾与 4.17 行迹均不依赖任何位置采集（行迹=攻略数据聚合）。

三、用户旅程与使用场景

以「下月去大理和丽江玩五天」为示例场景，把产品按时间轴走一遍——每个阶段右侧标注对应的功能模块，模块详述见第四章。

  1. T-2 周 · 逛城市、攒心愿

    打开拾程首页：一张水墨中国地图，搜「大理」或直接点滇西的小印 → 水墨晕染转场下钻 → 地图自动标注热门景点/美食/酒店（篆刻印章+毛笔小楷）。看到心动的点「收藏」进心愿池，不急着定哪天。【模块：首页/城市下钻/热门榜/收藏池】

  2. T-1 周 · 排日程、连线选交通

    新建攻略「大理 · 5日」→ 把心愿池里的点分到各天，拖拽调序 → 相邻点自动连线 → 点连线选交通：从民宿到崇圣寺三塔选「打车」，地图上淡赭线路上跑一辆朱砂小车、挂 18 分钟时长牌；古城内点「步行」，淡青虚线加脚印、22 分钟。住宿设为驻地锚点。【模块：日程编排/交通段/智能辅助/时间推算】

  3. T-1 天 · 拆锦囊

    出发前一天打开攻略：顶部浮起一只锦囊，拆封（动效）——穿衣建议、预算余量、首站出发时间、天气诗句。【模块：行前锦囊/天气】

  4. T 日 · 走在路上

    「今天」视图自动激活：按时间高亮当前/下一项；到点时朱砂条提醒「现在出发，步行 25 分钟」；点「导航」唤起腾讯地图；到了崇圣寺点「已至」——印章盖落。中午记账预填估算的打车费。下午预报有雨？收藏池里的博物馆一键换上。【模块：今天视图/该出发了/导航唤起/盖章/记账/雨备】

  5. T+1 日 · 回顾与沉淀

    行程结束后攻略转「回顾态」：已至印章分布、花费曲线、题跋集；归档进「已行卷」；首页中国地图上大理的城市印记盖「行」字。导出一张国风长卷发朋友圈；此后切到「行迹」态，历次行脚汇于一图。【模块：忆游回顾/归档/城市印记/行迹/导出】

桌面主场景

出发前在家中/办公室用大屏做攻略：地图满屏 + 左侧日程栏 + 右侧抽屉（时间轴/记账切换）+ 鼠标拖拽编排。编辑效率优先。

移动主场景

出行当天用手机：PWA 落桌面一击即达；地图恒为背景，bottom sheet 三档拖拽切换「今天」清单与记账；一键唤起腾讯地图 App 导航。

4.5 日程编排

  • 日程面板（DayPanel）：选中日的 POI 有序列表：每项显示 到达/离开时间（推算）、停留时长（可改）、类别印、题跋按钮；项间为「交通条」。
  • 拖拽排序：桌面拖拽项内重排（松手后自动重连线与时间重算）；移动端用项菜单「上移/下移」。
  • 跨日：拖拽跨 Day 或「移到第 N 日」菜单；移动后该 POI 在两日的交通段自动重算。
  • 驻地：住宿类入日程时问「设为驻地？」（默认是）→ 进入 Day 的 base 槽位；换酒店=换锚点，时间轴夜间「宿 · XX」小卡随之更新；同酒店多晚自动重复显示宿卡。
  • 删除：项菜单「移出」→ 确认 → toast「已移出 · 撤销」；该点退回收藏池，相邻交通段重算。
  • Day 操作：加一天（尾部）/ 删空的一天（倒数）/ 改标题（主题日）/ 查看该日天气条。
  • 重复加入：同一 POI 加入已含它的 Day 时提示「已在第 N 日」，仍允许（美食场景）。
  • 即时保存：所有操作即时写 localStorage，无保存按钮，刷新不丢。

4.8 时间推算

  • 算法：从当日出发时间（默认 09:00，Day 可改）起，按「交通段时长 → 到达 → 停留 → 离开 → 下一交通段」串联；驻地不占白天时段，日尾追加「宿 · XX」小卡。推算结果实时渲染到日程面板与时间轴。
  • 停留默认值（按类别，可在 POI 上改）：景点 90 分钟 / 美食 60 / 购物 60 / 自定义点 30 / 车站 20 / 驻地 0（不占白天）。
  • 改动联动：任一交通方式/停留时长/顺序/出发时间变更 → 该日全量重算（纯本地计算，无网络）。
  • 展示：到达时刻 HH:MM（Cormorant 数字）+ 停留「90 分」；估算交通段的时刻挂「估」。

阶段 Phase 4（算法）+ Phase 6（时间轴完整呈现）。

4.9 地点卡片与搜索

  • 宣纸地点卡片（PlaceCard）：点任一 POI 印章弹出。内容：封面图（Unsplash 直链，失败降级水墨渐变+类别图标）+ 名称（+类别小印）+ 评分 ★4.7 + 人均 ¥80 + 营业时间 + 标签胶囊 + 简介 + 操作钮「收藏 / 加入日程 / 导航 / 记一笔 / 题跋」。
  • 搜索框：编辑器顶部悬浮；范围=当前城市；300ms 防抖；调 WebService 地点搜索 suggestion；结果列表复用 PlaceCard；无 Key 时搜索种子数据 + 热门榜内过滤，并标注「演示数据」。
  • 导航：卡片点「导航」→ 出行方式弹层 → 移动端 qqmap:// 唤起腾讯地图 App（带起终点坐标）；Web 端降级跳 apis.map.qq.com/uri/v1/ 路线页；均不可用时弹演示提示。
  • 记一笔：卡片直接新建开销（4.13），预填：日期=该 POI 所在日、关联 poiId、分类按类别猜（美食→餐饮、景点→门票）。
  • 题跋：卡片一角毛笔图标 → 小楷输入一句手记（≤50 字），存 POI.note，导出呈题跋。
  • 真实底图原生 POI（D107，v4.8）：有 Key 时，腾讯底图自带的酒店/餐馆/学校等原生地点均可点击（point 要素常开，click 事件取 evt.poi），弹同一张 PlaceCard；异步用地点搜索 suggestion 精确匹配补全类别、评分、人均、开放时间，匹配不到用逆地理编码补地址。临时以 source:'map' 落库。只弹详情、不自动加入日程——加不加由用户点「加入日程」决定；拖动/长按时吞掉点击避免误触。
  • 推荐点注名（D104）：地图上的推荐/热门地点平时只显示方印章，名称仅悬浮或选中时显现，避免一整片文字盖住地图（配合 D79 抗遮挡锚点与去重）。

4.10 自定义落点与朱笔批注

5.1 设计理念

Purpose：把「出发前做功课」与「在路上解决衣食住行」合二为一的国风旅行地图——吃/住/玩/天气串成一张看得全的水墨长卷，每笔开销、每段时间都在宣纸上有据可查。

Aesthetic Direction：宋韵雅致 · 文人山水长卷。以宋代文人审美为骨：米白宣纸为底，淡青（汝窑天青）与淡赭为主色，墨色勾线，朱砂小印点睛。追求「留白、克制、雅致」——大面积空纸、细劲线条、低饱和设色，如一幅可交互的《千里江山》手卷局部，而非信息仪表盘。地图是水墨山水底图（远山淡影、河流留白、宣纸纤维纹理），POI 用篆刻印章形标记与毛笔小楷标注，路线似一笔淡墨勾连。

负面清单（用户验收红线）：无紫色、无蓝紫渐变；禁 emoji 图标；非居中卡片堆叠的模板感；禁 Inter/Roboto/Arial/system-ui 字体。

5.7 动效体系（晕 · 落 · 展 · 行）

动效观（D59）：动效不是装饰，是「笔墨的物理感」——全站动效统一归入四个语法动词，新增动效先归入其一，归不进去的就不做；所有动效一律经 src/lib/motion.ts 调用（全站唯一动效入口，便于统一降级）。

动词意象用于典型载体
晕墨滴入纸，由点及面遮罩、加载、聚焦、背景压暗、消散（反向）Lottie / CSS radial mask
落印章盖落，力透纸背一切「确认」反馈：已至盖章、城市印记、入池、创建确认anime scale + CSS 印泥微渗
展卷轴徐展，信笺启封一切「打开」：抽屉、弹窗、锦囊、回顾页、小卷CSS translate/clip-path
行笔走龙蛇，车马行路一切「过程」：描边绘制、沿路径运动、数字滚动anime stroke-dashoffset / path

三纪律：① 反馈优先——用户操作的反馈动效（按压/盖章/入池）永不省略，装饰动效可砍；② 一屏两动——同屏非反馈动效并发 ≤2，stagger 单枚间隔 30–60ms、整组 ≤1.2s；③ 可静可断——prefers-reduced-motion 全站降为 ≤120ms 透明度简动，低端机走 6.9 降级矩阵，动效永不长时间拦截点击。

6.6 时间推算与估算算法

时间推算（timeline.ts 纯函数）

// 输入 DayPlan + segments + pois → 派生 TimelineEntry[]
// 停留默认：sight 90 / food 60 / shop 60 / custom 30 / transport 20 / base 0（不占白天）
function deriveDay(day, pois, segments): TimelineEntry[] {
  let t = parse(day.departTime ?? '09:00')
  const out: TimelineEntry[] = []
  const stops = day.poiIds.filter(id => pois[id].role !== 'base')
  for (const poiId of stops) {
    const seg = segments.find(s => s.toPoiId === poiId && day.segmentIds.includes(s.id))
    if (seg) { t = addMin(t, seg.durationMin); out.push({ kind:'move', time:fmt(t), segmentId: seg.id }) }
    const arrive = fmt(t)
    const stay = pois[poiId].stayMinutes ?? DEFAULT_STAY[pois[poiId].category]
    t = addMin(t, stay)
    out.push({ kind:'poi', time:arrive, poiId, arrive, leave: fmt(t) })
  }
  if (day.basePoiId) out.push({ kind:'stay', label:`宿 · ${pois[day.basePoiId].name}` })
  return out   // 跨城日由 Day 城市不同自动插 divider：「翌日 · 赴{city}」
}

无 Key 直线估算（estimate.ts）

// 两点直线距离（GCJ-02 短距平面近似）× 经验速度 + 诚实「估」标记
const SPEED = { walk: 4.5, bike: 12, taxi: 30 /*km/h，另加起步 5min*/ } // transit 不估，提示需 Key
function estimate(from: LngLat, to: LngLat, mode: TransportMode) {
  const d = haversineFlat(from, to)          // km
  const durationMin = mode === 'taxi'
    ? Math.ceil(d / SPEED.taxi * 60) + 5 : Math.ceil(d / SPEED[mode] * 60)
  return { durationMin, distanceKm: round1(d), estimated: true }
}

智能辅助阈值集中为常量表（4.7 表格的数值），便于调参与测试。

6.7 缓存与配额策略

  • 热门榜：每城市每类别只拉一次，长期缓存（`shicheng:hot:{city}:{cat}`）——个人 Key 地点搜索配额（约 200 次/天）的最大保护。
  • 搜索：300ms 防抖 + 会话内结果缓存（同关键词不重发）。
  • 路线：段级缓存键 `from|to|mode`，改方式才重算；行程重排不重拉（两点不变）。
  • 天气：24h TTL + 行前临近自动更新；Open-Meteo 请求 8s 超时降级。
  • 配额耗尽表现：搜索返回空 + 提示「今日实时搜索额度已尽，可先浏览种子/已缓存数据」。

6.8 坐标系纪律

  • 全应用 POI/路线/地图交互统一 GCJ-02（腾讯系）。
  • Open-Meteo 查询用 WGS-84：按城市中心点换算（城市中心级别的偏移对预报无影响，代码处显式注释两坐标系来源，禁止逐 POI 混算）。
